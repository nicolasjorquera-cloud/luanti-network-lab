# Luanti server container

Base image with Luanti server + the **Mineclonia** subgame.

## Build

```bash
podman build -t localhost/luanti-network-lab/luanti:latest server/luanti
```

## Layout

- `/var/lib/luanti/world` — persistent world (volume)
- `/usr/share/luanti/games` — Mineclonia subgame (baked into the image)
- `/etc/luanti/minetest.conf` — server config (mounted read-only)

## Deployment mechanisms

Two ways are provided to run the container; **the explicit systemd unit is the
canonical mechanism**, quadlet is the alternative:

- **Canonical:** `luanti.service` (a `Type=simple` user unit), generated by
  `scripts/deploy-luanti-service.sh`. Reliable on user managers where the podman
  system generator may not re-run.
- **Alternative:** `luanti.container` + `luanti.pod` (quadlet), for hosts where
  `podman-system-generator` is available.

Both share the same image (`localhost/luanti-network-lab/luanti:latest`), the
same named volume (`luanti-world:/var/lib/luanti/world`), and publish UDP 30000
only to the host's Tailscale IP (zero-trust). See
`docs/specs/2026-08-23-deploy-mechanism-unification.md`.
