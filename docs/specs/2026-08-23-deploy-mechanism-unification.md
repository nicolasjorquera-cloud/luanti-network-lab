# Deploy mechanism — document canonical vs. alternative

**Date:** 2026-08-23
**Status:** Approved
**Author:** nicolasjorquera-cloud
**Scope:** Phase 1 — deployment documentation (no runtime changes)

## 1. Problem

The repo currently provides **two ways** to run the Luanti container:

- **Explicit `Type=simple` systemd user unit** — `server/luanti/luanti.service`,
  generated by `scripts/deploy-luanti-service.sh`. This is the **live
  deployment** in use.
- **Quadlet units** — `server/luanti/luanti.pod` + `server/luanti/luanti.container`,
  marked "non-default / alternative".

The README (`server/luanti/README.md`) already notes the live deployment is the
explicit unit. The ambiguity is whether these are peers, or one is canonical and
the other a fallback. This spec resolves that without touching any container file
or runtime.

## 2. Decision

- **Canonical:** the explicit `Type=simple` unit generated by
  `scripts/deploy-luanti-service.sh`. Reliable on user managers where the
  podman system generator may not re-run (see ROADMAP "Errors encountered" and
  `docs/architecture.md`).
- **Alternative:** quadlet (`luanti.pod` / `luanti.container`), for hosts where
  `podman-system-generator` is available.
- **No container files or runtime are modified.** This is documentation and
  conceptual alignment only.

## 3. Conceptual alignment (no runtime change)

Both mechanisms must be documented as using the same:

- Image: `localhost/luanti-network-lab/luanti:latest`
- Named volume: `luanti-world:/var/lib/luanti/world`
- Port: UDP `30000`, bound to the host's Tailscale IP only (zero-trust)

Documenting these shared facts prevents the two paths from silently diverging.

## 4. Where it is documented

- `server/luanti/README.md` — state the canonical mechanism and the alternative,
  and that they share image/volume/port.
- `docs/architecture.md` — already mentions both; sharpen the wording to label
  the explicit unit as canonical and quadlet as alternative.

## 5. Non-goals

- No edits to `luanti.pod`, `luanti.container`, or `luanti.service`.
- No runtime changes, no migration.
